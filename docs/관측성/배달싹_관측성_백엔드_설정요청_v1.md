### 1-2. 서비스별 `application.yml` 변경 내용 (6개 동일)

기존 `management:` 블록에서 `include` 줄을 바꾸고, `otlp` · `logging` 두 항목을 추가

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,prometheus   # 변경: prometheus 추가
  otlp:                                    # 추가
    metrics:
      export:
        enabled: false                     # 지표는 Prometheus 가 수집 — OTLP 중복 전송 끔
  logging:                                 # 추가
    export:
      otlp:
        enabled: false                     # 로그는 stdout → Fluent Bit → Loki — OTLP 중복 전송 끔
```

- 기존 `management:` 아래 다른 설정(`endpoint.health` 등)은 그대로 둠
- 이유는 3-2 · 4-2 표 참고

## 3. 지표 — Prometheus

### 3-1. 설정값

루트 `build.gradle` (서비스 모듈 공통 블록)

```groovy
// 변경 전
// runtimeOnly    'io.micrometer:micrometer-registry-prometheus'          // /actuator/prometheus

// 변경 후
runtimeOnly 'io.micrometer:micrometer-registry-prometheus'                // /actuator/prometheus
```

6개 서비스 `application.yml`

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,prometheus
```

### 3-2. 이렇게 설정한 이유

| 항목 | 이유 |
| --- | --- |
| 루트 `build.gradle` 에 넣음 | 인프라 Prometheus 가 6개 서비스를 모두 수집 대상으로 등록해 둠 (현재 6개 모두 404). 서비스별로 넣으면 빠진 서비스는 계속 404 |
| `runtimeOnly` | 코드에서 직접 쓰지 않음. 실행 시에만 필요 |
| 버전 미기재 | Spring Boot BOM 이 관리 (`micrometer-core` 와 같은 1.16.7 로 맞춰짐) |
| `exposure.include` 에 `prometheus` 추가 | 의존성만 넣으면 엔드포인트가 열리지 않음. Spring Boot 는 노출 목록에 있는 것만 HTTP 로 공개 |
| 포트 8081 | 인프라 차트가 `MANAGEMENT_SERVER_PORT=8081` 을 주입. actuator 는 8081 에서만 열리고 ALB(8080)로는 나가지 않음 |
| `health,info` 유지 | probe(`/actuator/health/liveness` · `readiness`)가 사용 중 |

## 4. 추적 — Brave → OpenTelemetry 전환

### 4-1. 설정값

루트 `build.gradle` (서비스 모듈 공통 블록)

```groovy
// 변경 전
implementation 'org.springframework.boot:spring-boot-micrometer-tracing-brave'
implementation 'io.micrometer:micrometer-tracing-bridge-brave'

// 변경 후 (두 줄 삭제, 한 줄 추가)
implementation 'org.springframework.boot:spring-boot-starter-opentelemetry'
```

6개 서비스 `application.yml`

```yaml
management:
  otlp:
    metrics:
      export:
        enabled: false        # 지표는 Prometheus 가 수집 (OTLP 로 중복 전송 안 함)
  logging:
    export:
      otlp:
        enabled: false        # 로그는 stdout → Fluent Bit → Loki (OTLP 로 중복 전송 안 함)
```

### 4-2. 이렇게 설정한 이유

| 항목 | 이유 |
| --- | --- |
| OpenTelemetry 로 전환 | 관측 데이터 업계 표준(CNCF). 전송 형식 OTLP 를 Tempo · Jaeger · 상용 APM 대부분이 받음. Spring Boot 4 가 전용 starter 제공 |
| Brave 2줄 삭제 | 추적 라이브러리는 한 앱에 하나만 둠. Brave 와 OpenTelemetry 를 같이 두면 Tracer 가 2개 생겨 자동 설정이 어느 쪽을 쓸지 보장되지 않음 |
| 루트에서 바꿈 | 6개 서비스가 같은 추적 라이브러리 · 같은 헤더 형식을 써야 주문 → 결제 → 배달이 traceId 하나로 이어짐. 서비스별로 다르면 중간에서 끊길 수 있음 |
| `management.otlp.metrics.export.enabled: false` | starter 에 `micrometer-registry-otlp` 가 포함됨 (7장). 끄지 않으면 지표를 OTLP 로도 보내려 하고, 받을 곳(기본 `localhost:4318`)이 없어 1분마다 오류 로그 |
| `management.logging.export.otlp.enabled: false` | starter 에 OTLP 로그 전송 기능이 포함됨. 로그는 이미 Fluent Bit 가 수집 → 이중 전송 방지 |
| 바뀌지 않는 것 | 로그의 `traceId` · `spanId` 필드 이름, MQ 헤더 전달(`observation-enabled`), gateway `context-propagation: auto` |

## 5. 추적 — Tempo 전송 주소

### 5-1. 설정값

| 위치 | 설정 | 값 | 누가 |
| --- | --- | --- | --- |
| AWS (EKS) | 환경 변수 `MANAGEMENT_OPENTELEMETRY_TRACING_EXPORT_OTLP_ENDPOINT` | `http://tempo.monitoring.svc.cluster.local:4318/v1/traces` | 인프라가 6개 서비스에 주입 |
| 로컬 | 없음 | — | — |
| `application.yml` | 넣지 않음 | — | — |

이미 설정되어 있어 그대로 두는 값 (6개 서비스 모두 확인)

| 설정 | 현재 값 | 의미 |
| --- | --- | --- |
| `management.tracing.sampling.probability` | `1.0` | 요청 100% 추적 (Spring 기본값 0.1 = 10%) |
| `spring.rabbitmq.template.observation-enabled` · `listener.simple.observation-enabled` | `true` (gateway 제외 5개) | 메시지 발행 · 소비 시 traceId 를 헤더로 전달 |
| gateway `spring.reactor.context-propagation` | `auto` | WebFlux 에서 traceId 유지 |

### 5-2. 이렇게 설정한 이유

| 항목 | 이유 |
| --- | --- |
| 주소를 환경 변수로 받음 | 백엔드 규칙: 주소는 환경 변수로만 (하드코딩 금지). Spring 은 `MANAGEMENT_OPENTELEMETRY_TRACING_EXPORT_OTLP_ENDPOINT` 를 `management.opentelemetry.tracing.export.otlp.endpoint` 로 읽음 |
| 설정 이름 | Spring Boot 4.0.8 기준 이름 (`spring-boot-micrometer-tracing-opentelemetry` 메타데이터 확인). 3.x 이름 `management.otlp.tracing.endpoint` 는 쓰지 않음 |
| HTTP · 4318 | starter 기본 전송 방식이 HTTP (`transport = http`). gRPC(4317)는 쓰지 않음 |
| 로컬은 주소 없음 | 주소가 없으면 전송하지 않음. traceId 는 로그에 계속 찍힘 |

## 6. 로그 — 변경 없음

| 항목 | 현재 설정 | 인프라에서 쓰는 방식 |
| --- | --- | --- |
| 형식 | `logging.structured.format.console: logstash` (6개 서비스) | Fluent Bit 가 JSON 을 풀어 필드로 저장 |
| `level` | logstash 형식에 포함 | Loki 라벨 (`level="ERROR"` 로 필터) |
| `traceId` | MDC → JSON 필드 | 본문 검색 (`\|= "<traceId>"`) — 라벨로 쓰지 않음 |
| 출력 위치 | stdout | 파일 로그 · 별도 appender 불필요 |

- Loki 라벨: `namespace` · `service` · `level` 3개만 (라벨이 늘면 Loki 인덱스가 커짐)
- `service` 라벨은 인프라 차트가 파드에 붙임 (백엔드 작업 없음)
